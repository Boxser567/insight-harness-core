# Agent Note：设置对话框控制器

状态：已实现

[English](2026-08-28-settings-dialog-controller.md) | 中文

## 问题

Client 插件可以提供设置分区，但只有 `ui-settings-general` 所有的设置触发器能够打开共享设置外壳。需要提供「设置」操作的产品集成若无正式能力，只能定位私有 DOM 并模拟点击，或渲染第二个设置对话框，从而依赖 slot API 并未承诺的呈现细节。

## 决策

`ui-settings-general` 提供带有 `open(sectionId?)` 的 `ctx.settingsDialog`。该服务打开现有设置外壳并请求一个已注册分区；缺少或无法识别的 id 使用当前首个分区。它只控制界面呈现，不注册、读取或修改设置。

`SettingsDialogController` 不持有 React 状态。设置 slot 注册将控制器连接到共享 owner store，并在注销时断开。该时间段之外的调用会失败，而不会为以后或替代挂载排队；第二个并发设置外壳所有者会被拒绝。

Cordis 服务与 slot 注册共享提供方插件的生命周期。插件卸载会移除服务；后续重新激活会创建新的控制器和外壳连接。

外壳将产品拥有的 `settings.launcher` 与 Connection 拥有的恢复状态组合呈现。共享模态组件负责恢复焦点。null 入口会隐藏空行，但不注销对话框服务。

## 曾考虑的替代方案

**在 DOM 中定位设置触发器并点击。** 否决，因为 DOM 结构、class 与事件所有权属于私有呈现细节，不是 client 扩展 API。

**把对话框状态移入 `ui-settings` 底座包。** 否决，因为该包持有设置领域和 slot 声明且不依赖呈现包；模态框及其局部查看状态已经归 `ui-settings-general` 所有。

**让每个产品插件渲染自己的设置对话框。** 否决，因为重复外壳会拆分导航、无障碍行为和设置呈现的所有权。

## 后果

Client 插件获得一个与具体产品无关的「打开设置」操作，而现有触发器、Escape 处理、焦点行为、分区账本和设置数据所有权保持不变。该 API 有意不提供关闭、切换或设置变更方法；新增操作需要确实存在的跨插件用例，而不能整体暴露组件状态。

slot 注册前明确失败可以立即暴露加载顺序或外壳缺失问题。从已渲染 UI 发起调用天然发生在注册后；可能更早运行的代码必须等待自身 UI 可用，而不能依赖延迟执行的全局操作。
